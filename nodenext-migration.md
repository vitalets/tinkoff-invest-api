# NodeNext Migration Notes

When switching `tsconfig.json` from `"module": "ESNext", "moduleResolution": "node"` to
`"module": "NodeNext", "moduleResolution": "NodeNext"` the following errors need to be fixed.

## Errors & Fixes

### 1. `long` node_modules type error (TS1479)

```
node_modules/long/umd/index.d.ts(1,18): error TS1479:
The current file is a CommonJS module whose imports will produce 'require' calls;
however, the referenced file is an ECMAScript module and cannot be imported with 'require'.
```

**Fix:** Add `"skipLibCheck": true` to `tsconfig.json` compilerOptions.

---

### 2. `descriptor.ts` — missing `.js` extension (TS2307)

```
src/generated/google/protobuf/descriptor.ts(3,17): error TS2307:
Cannot find module 'protobufjs/minimal' or its corresponding type declarations.
```

`descriptor.ts` was generated by ts-proto without the `.js` extension; all other generated
files already use `"protobufjs/minimal.js"`. NodeNext requires explicit file extensions.

**Fix:** `src/generated/google/protobuf/descriptor.ts`
```diff
-import _m0 from "protobufjs/minimal";
+import _m0 from "protobufjs/minimal.js";
```

---

### 3. `helpers.ts` — `ms` named export `StringValue` (TS2305 / TS2497)

```
src/helpers.ts(6,14): error TS2305: Module '"ms"' has no exported member 'StringValue'.
src/helpers.ts(6,33): error TS2497: This module can only be referenced with ECMAScript
imports/exports by turning on the 'allowSyntheticDefaultImports' flag and referencing
its default export.
```

The project uses `ms@^3.0.0-beta.2` which ships its own types with `StringValue`.
However `@types/debug` (a devDependency) transitively pulls in `@types/ms@0.7.31`, which
shadows the bundled types with an older `export = ms` declaration that has no `StringValue`.

Under NodeNext, TypeScript picks the wrong types, causing both errors.

**Fix:** `src/helpers.ts`
```diff
-import ms, { StringValue } from 'ms';
+import ms from 'ms';
 ...
-    const offsetMs = typeof offset === 'string' ? ms(offset as StringValue) : offset;
+    const offsetMs = typeof offset === 'string' ? ms(offset) : offset;
```

The `as StringValue` cast is unnecessary at runtime; removing it also fixes the
`Operator '+' cannot be applied` (TS2365) errors that followed because `@types/ms`
typed `ms(string)` as returning `number` but the old overload returned `string | number`.

---

### 4. `stream/base.ts` — `TypedEmitter` used as a type (TS2709)

```
src/stream/base.ts(25,45): error TS2709: Cannot use namespace 'TypedEmitter' as a type.
```

`typed-emitter@2.1.0` has `"main": "./types.js"` with no `"exports"` map, so under
NodeNext TypeScript treats it as a CommonJS namespace rather than an ES module interface.
`import type` does not help here because the package itself has no `"type": "module"`.

**Fix:** Replace the `typed-emitter` import with an inline type alias in `src/stream/base.ts`:
```diff
-import TypedEmitter from 'typed-emitter';
+type TypedEmitterFixed<Events extends Record<string, (...args: any[]) => void>> = {
+  addListener<E extends keyof Events>(event: E, listener: Events[E]): EventEmitter;
+  on<E extends keyof Events>(event: E, listener: Events[E]): EventEmitter;
+  // ... (see full definition)
+};
 ...
-  protected emitter = new EventEmitter() as TypedEmitter<InternalEventMap<Req, Res>>;
+  protected emitter = new EventEmitter() as TypedEmitterFixed<InternalEventMap<Req, Res>>;
```

Alternatively, open a PR / issue on `typed-emitter` to add an `"exports"` map, or replace
the package with the built-in `EventEmitter` generic overload from `@types/node`.

---

### 5. `stream/market.ts` — implicit `any` on error parameter (TS7006)

```
src/stream/market.ts(50,30): error TS7006: Parameter 'error' implicitly has an 'any' type.
```

Caused by `strict` mode + the `close` event listener losing its inferred type when
`TypedEmitterFixed` returns `EventEmitter` instead of `this` for fluent chain methods.

**Fix:** `src/stream/market.ts`
```diff
-    this.emitter.on('close', error => this.onClose(error));
+    this.emitter.on('close', (error?: Error) => this.onClose(error));
```

---

### 6. `test/specs/stream.spec.ts` — missing `.js` extension (TS2835)

```
test/specs/stream.spec.ts(4,23): error TS2835: Relative import paths need explicit
file extensions in ECMAScript imports when '--moduleResolution' is 'node16' or 'nodenext'.
Did you mean '../helpers.js'?
```

**Fix:** `test/specs/stream.spec.ts`
```diff
-import { omits } from '../helpers';
+import { omits } from '../helpers.js';
```

Check the rest of the test and source files for any other relative imports missing `.js`.
The generated files and `src/` already use `.js` extensions throughout.
